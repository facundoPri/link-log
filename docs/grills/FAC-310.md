### Long description

> Linklog's Browser view lists the tabs open in your Chrome windows, so you can review them, group them and save the ones you want to keep.
>
> **What you can do**
> - See every open tab with its preview, and filter by domain.
> - Turn on lenses: questions you define, answered by AI from the page, to sort tabs you want to keep from tabs you can close.
> - Group, move, open and close the tabs you select, and put idle tabs to sleep.
> - Save a tab to your Linklog library. Saving is a separate action; evaluating a tab with a lens doesn't save it.
>
> **What the extension reads, and when**
> - Nothing until you click "Accept and connect" on its Connect page.
> - Then: the URL and title of your open tabs and your tab groups. The tabs of Linklog's window are shown to your Linklog page.
> - Page text and previews only if you also click "Allow page content". You can remove that access on the same page.
> - Page text leaves your browser only when a lens you turned on evaluates a tab. It goes to your Linklog library, which uses a remote AI provider for the answer.
> - Saving a tab sends only its URL. Linklog then fetches the page with a remote extraction service, like any link you add.
> - Never cookies, passwords or form fields. Your data isn't sold or used for ads.
>
> **Permissions**
> - Tabs: read your open tabs (Chrome calls this "Read your browsing history").
> - Tab groups: show and change the groups you choose.
> - Scripting and optional site access: read the pages you allow.
> - Storage: keep results and your settings.
> - linklog.facundopri.com: connect to the Linklog web app.
>
> **Requirements**: a Linklog account and desktop Chrome.
>
> Privacy policy: https://linklog.facundopri.com/privacy

## Privacy practices tab

### Single purpose (266 characters; this field has no 132 limit)

`Connects Linklog's Browser view to the tabs and tab groups of the user's Chrome windows, so they can review, group, close and save their open tabs in Linklog. Reading open pages for previews and lenses, only when the user allows page content, is part of that review.`

This is the ticket's proposal plus one sentence that puts page reading inside the purpose, so a reviewer doesn't read it as a second function. "Windows" is plural because the probe shows the extension reads every window.

### Permission justifications

- **`tabs`**: "Browser view lists the user's open tabs so they can review them. The extension needs `tabs` to read each tab's URL, title and icon, and to group, move, open, put to sleep and close the tabs the user selects. Nothing is read until the user accepts the disclosure on the extension's Connect page. Tab URLs and titles are shown to the user's Linklog page. They leave the browser only when the user turns on a lens or saves a tab: then the URL goes to the user's Linklog library, and for lenses so does the page text."
- **`tabGroups`**: "To show the user's tab groups in Browser view, and to create, rename, recolor, move and ungroup them when the user groups tabs from Linklog. The title, color and description of a group the user links to Linklog are kept in local storage, so the link survives a Chrome restart."
- **`scripting`**: "To run the extractor bundled in the package (`extract.js`, no remote code) in open tabs where the user granted page access, and read the title, description, preview image and page text for previews and lenses. It never runs on pages without a user-granted host permission."
- **`storage`**: "`chrome.storage.session` holds the open-tab registry, lens results per tab and the load queue, cleared when Chrome closes. `chrome.storage.local` holds the user's consent, an installation id, the look of linked tab groups and the chosen load concurrency."
- **Optional host permissions `http://*/*`, `https://*/*`**: "Browser view reviews whatever tabs the user has open, on any site, so the sites can't be listed in advance. Access is requested only when the user clicks 'Allow page content' on the Connect page, after the disclosure, and can be removed there at any time. Chrome's Site access can also limit it to specific sites, and the extension honors that per tab. It is used only to run the bundled extractor in the tabs the user reviews: no cookies, no form fields, no history, no page changes, no reloading or scrolling. Page text leaves the browser only when a lens the user turned on evaluates a tab."
- **Host access `https://linklog.facundopri.com/*` (bridge content script)**: "Connects the Linklog web app to the extension. The script stays inert unless the page identifies as Linklog, and only relays validated messages between that page and the extension."

### Remote code

**"No, I am not using remote code."** All JavaScript is in the package. `extract.js` is injected from the package by file. The CSP is `script-src 'self'; object-src 'self'`. The extension makes no network requests (measured).

### Data usage

**Decided by the FAC-307 arena (PR #56, D4), not here.** The owner asked there for consistency with the policy. The form certifies that the answers "reflect … your privacy policy", and that policy covers the whole item (the account as well as the extension), so the boxes follow what the policy says Linklog collects. This replaces this arena's first draft of only two boxes, which counted the extension alone.

| Box | Ticked | Why |
| --- | --- | --- |
| Personally identifiable information | Yes | Account email and name |
| Authentication information | Yes | Password hash, sign-in links |
| Location | Yes | IP address |
| Personal communications | Yes | Saved social media posts, which the dashboard's own example names |
| Web history | Yes | Tab URLs and titles from the extension |
| Website content | Yes | Page text, description and images from the extension |
| Health, Financial and payment, User activity | No | Not collected. Tab events only keep the list current; they are web history, not activity monitoring. |

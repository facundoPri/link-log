# FAC-306: store build with production-only origins and a compliant 128px icon (grilling decisions)

**Status: accepted by the owner (2026-11-26)**, together with [FAC-305](FAC-305.md#owner-answers-2026-11-26). The owner was asked nothing for this ticket: every choice was technical. The tickets in Linear carry the decision. Decided in the same arena as [FAC-305](FAC-305.md); the process is in [FAC-305-process.md](FAC-305-process.md), the prototype in [FAC-305-306-prototype.diff.txt](FAC-305-306-prototype.diff.txt) and the probes in [FAC-305-306-tools/](FAC-305-306-tools/).

## Measured facts

- `LINKLOG_ORIGINS=https://linklog.facundopri.com bun run extension:package` reproduces the released `extension-v0.2.1` ZIP: the manifest and JS are byte-identical. It holds 13 files, with no maps, tests, fixtures or env files.
- `gh variable list`: `EXTENSION_ORIGINS=https://linklog.facundopri.com`.
- Install warnings, from Chrome for Testing 153, `chrome.management.getPermissionWarningsByManifest`:

  | Build | Install warnings |
  | --- | --- |
  | Released 0.2.1 | "Read and change your data on 127.0.0.1, linklog.facundopri.com, and localhost" · "Read your browsing history" · "View and manage your tab groups" |
  | **Store build (decided)** | "Read and change your data on linklog.facundopri.com" · "Read your browsing history" · "View and manage your tab groups" |
  | Without the bridge content script | only the last two |

  The bridge's content-script matches show up as granted host permissions in `chrome://extensions`, and that is where the first line comes from. The optional host permissions don't appear at install.
- The "Allow page content" grant dialog says "Read and change all your data on all websites". For one site: "Read and change your data on github.com". For four sites: "…on a number of websites".
- Icon: `128.png` fills its whole canvas (art bounding box 0..127). So do 16, 32 and 48.

## Decisions

1. **One artifact for the store and GitHub.**
   - `--package` builds a bridge that matches only `LINKLOG_ORIGINS`, with no `localhost` or `127.0.0.1`.
   - It fails if `LINKLOG_ORIGINS` is empty or not https: "A packaged build bridges only LINKLOG_ORIGINS, which must be https (got: …)".
   - Dev builds (`extension:build`, `extension:dev`, `extension:ego`, `test:browser`) keep localhost.
   - The guard matters: without it, a forgotten `EXTENSION_ORIGINS` would package an extension that matches nothing. User Data FAQ Q9 requires secure transport, and FAC-306 already calls http the problem.
2. **The GitHub ZIP drops localhost too.**
   - Its users are production users. People who run Linklog locally build from source, and the web's "missing" card already tells them to.
   - Two artifacts would mean two CI jobs, which grows scope.
   - The localhost bridge without pairing is an accepted risk in the handoff doc. Removing it from every shipped build is the mitigation that doc names.
3. **`EXTENSION_ORIGINS` stays `https://linklog.facundopri.com`.**
4. **Keep `optional_host_permissions` `http://*/*` and `https://*/*`, requested together from "Allow page content".**
   - Per-site would not change the manifest the reviewer reads. Arbitrary sites can only be covered by the same two wildcard patterns in `optional_host_permissions`, and the Privacy-tab justification is the same either way. So per-site buys no review safety; it only adds UX.
   - That UX would be large: `chrome.permissions.request` needs a gesture on an extension page for each new site, and previews for every tab and batch lenses would turn into N prompts.
   - Partial grants already work per tab: `hub.contentAccess()` checks every granted pattern. Users who want per-site control can set "On specific sites" in Chrome's Site access, and the code honors it.
   - **Fallback, not built:** if review rejects the all-sites scope, keep the manifest and change only the Connect button to request the origins of the currently open tabs in one gesture.
5. **Only `icons/128.png` gets the margin.**
   - The art is 96×96 with 16 px transparent on each side; measured bounding box 16..111. The store images rule is about the 128 icon.
   - 16, 32 and 48 stay full bleed. A margin at 16 px would make the toolbar glyph unreadable.
6. **The manifest `description` becomes the store short description**, because the store takes it from the manifest: "Review, group and save your open Chrome tabs in Linklog. It reads tab URLs and titles only after you accept." (108 characters.)
7. **Ship with FAC-305 in one PR, version 0.3.0.** Permissions can't change after publishing without disabling the extension for users, so the permission set is final before the first submission. Changing a permission later disables the extension until each user accepts.

### Why, against the criteria

- One artifact and one guard: no new build mode (1, 3).
- The change stays inside `build.ts` and the Connect status line (2).
- Every claim was measured on the unzipped package (4).
- Round 3 removed the moderator's extra `__LINKLOG_LOCAL_BRIDGE__` define. It existed only for one Connect status string, and the page can read `chrome.runtime.getManifest().content_scripts[0].matches` instead (one concept fewer).

## Alternatives dropped

- **A GitHub ZIP that keeps localhost.** Nobody needs it, it adds a warning line, and it needs a second artifact.
- **Per-site optional access.** It changes no review surface, and it needs a new UX in Connect and the web.
- **A margin on every icon size.** It shrinks the toolbar icon; the store doesn't ask for it.
- **Dropping the localhost acceptance in `isBridgeOrigin` at runtime as well.** That code is dead in the package (no content script matches localhost) and still serves dev builds. Changing the protocol helper adds scope.

## Proposed ticket changes (FAC-306)

Replace "Owner decision needed first" with "Decided (see `docs/grills/FAC-306.md`)". Acceptance criteria:

- `LINKLOG_ORIGINS=https://linklog.facundopri.com bun run extension:package` builds a ZIP whose `manifest.json` has `content_scripts[0].matches == ["https://linklog.facundopri.com/*"]`, `host_permissions == []`, the same 4 permissions, and optional `http://*/*`, `https://*/*`. The ZIP has no `localhost` or `127.0.0.1` anywhere in its manifest.
- `bun run extension:package` without `LINKLOG_ORIGINS`, or with an http origin, exits non-zero with a clear message. `LINKLOG_EXTRA_HOSTS` and `LINKLOG_EXTENSION_OUT` stay refused.
- A unit test covers `manifest()` for packaged and dev builds.
- Dev builds keep the localhost bridge (`bun run extension:build` prints it).
- `icons/128.png` measures 96×96 art with 16 px transparent margin (`iconbox.py`). 16, 32 and 48 are unchanged.
- The manifest `description` is the short description above.
- The install warnings of the packaged build, measured with `warnings.ts`, are recorded in the PR: exactly the three "Store build" lines above.
- The Connect status line reads the bridge origins from the manifest, with no build define.
- `extension-release.yml`: the `LINKLOG_ORIGINS` comment no longer says "empty builds a local-only extension".
- The handoff doc's mentions of the localhost bridge (§Permisos and §Límites) say it applies only to dev builds.
- The version rises to 0.3.0, shared with FAC-305, in one PR.
- `bun run test:browser` passes in one clean run on a quiet machine, with FAC-305's new unseeded consent check.
- How to verify: the commands above on the unzipped ZIP, then `bun run test:browser`.

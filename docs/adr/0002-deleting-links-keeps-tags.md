# Bulk delete keeps tag definitions, and skips links with a running job

Deleting selected links removes everything a link owns: its extracted content and previews in R2, its tag associations and tag evaluations, its lens results, media, hidden related links, and its queued and waiting jobs. Those jobs go with the link instead of being marked Cancelled, so they never run and Activity no longer counts them. Tag definitions stay, even when no link uses them any more: a tag is part of the owner's taxonomy and a candidate for auto-tag, not a property of one link. Lenses, batches and usage events stay for the same reason; a usage event keeps its cost with no link attached. A link whose job is already running is skipped and reported ("N still processing, skipped"), because its workflow may be about to store content. Content a workflow stores after its link was deleted is removed again at write time. Deleting asks for confirmation with the count and cannot be undone. The single-link delete in the Inspector predates this and still waits for any job to finish. Decided by the owner in FAC-46 (2026-11-24).

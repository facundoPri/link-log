# Usage costs are stored estimates at list price, and never shown as unknown

Each provider call stores its estimated cost when it finishes (`usage_events.estimated_usd`), so a new or changed rate needs a backfill migration instead of repricing at read time (four aggregations read the stored value). Estimates use the provider's list price, never net of free allowances such as Browser Rendering's monthly free hours, because a customer is charged for every call whatever our own plan gives us. A call cut short before it reported its units costs the average of the owner's recent finished calls to that service, and a call the provider refused before running it costs $0. Users never see an "unpriced" count: a finished call without a price is a pricing gap, logged as `usage_unpriced`. Decided by the owner in FAC-168 (2026-11-04).
